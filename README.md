## О проекте

Модуль `src/inventory.py` реализует складской учёт: позиции (`Item`), добавление,
списание, поиск, расчёт стоимости, поиск позиций с низким остатком и расчёт
стоимости со скидкой.

## Тесты

Файл `tests/test_inventory.py` содержит **26 тестовых функций (37 кейсов с
параметризацией)**. Используются:

- фикстуры `inventory` и `mixed_inventory`;
- `@pytest.mark.parametrize` для `Item` (имя), `add`/`remove` (количество),
  `apply_discount` (процент);
- `pytest.raises` для `ValueError`, `OutOfStockError`, `UnknownItemError`;
- `pytest.approx` для сравнения `float`.

Имена тестов в стиле `test_<что>_<условие>_<ожидание>`, каждый тест проверяет
одно поведение.

## Анализ результатов (Шаг 7)

1. **Процент покрытия:** 100 % по строкам и 100 % по ветвям.
2. **Непокрытые строки:** отсутствуют. Все ветвления (`if` в `Item.__post_init__`,
   `add`, `remove`, `find`, `low_stock`, `apply_discount`) проверены с обеих сторон.
3. **Наиболее ценные тесты:** тесты на `remove` (удаление позиции при обнулении,
   `OutOfStockError`) и на `add` (увеличение существующей позиции) — они проверяют
   ветвления, которые легко пропустить; тесты `apply_discount` с `percent=100`
   и `percent=0` — граничные значения.
4. **Дефекты модуля:** не обнаружены, все тесты проходят, `xfail` не требуется.
5. **Почему 100 % покрытия не гарантирует отсутствие дефектов:** покрытие
   показывает, что строка выполнена, но не что результат верный. Например,
   `total_value()` может быть покрыт тестом, который проверяет только тип
   результата, и при этом неверно суммировать позиции. В данной работе дефект
   вроде `round(..., 2)` вместо `round(..., 3)` не был бы поймён покрытием —
   только проверкой конкретного ожидаемого значения через `pytest.approx`.

## CI

Workflow `.github/workflows/tests.yml` запускает тесты на GitHub Actions при
`push` и `pull_request`, проверяет покрытие (`--cov-fail-under=85`) и публикует
`coverage.xml` как артефакт.
